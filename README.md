# Keitaro wrapper (FastAPI + SQLAlchemy)

Обёртка над рекламным трекером Keitaro из двух частей:

1. **Создатель кампаний.** По названию, гео-кодам и офферу создаёт в Keitaro кампанию с настроенными
   доменом, группой и источником и двумя потоками: страны из `Geo` уходят на Google, весь остальной трафик
   на выбранный оффер.
2. **Редактор потоков.** Загружает потоки кампании, позволяет добавлять и удалять офферы, закреплять доли
   и отправлять изменения в Keitaro кнопкой `PUSH TO KT`.

Стек: Python 3.10+, FastAPI, SQLAlchemy 2, Alembic, httpx. Интерфейс: один HTML-файл с JavaScript, без сборки.

## Запуск

```bash
# 1. Виртуальное окружение и зависимости
python -m venv .venv
source .venv/bin/activate          # Windows (cmd): .venv\Scripts\activate
pip install -r requirements.txt

# 2. Настройки
cp .env.example .env               # Windows: copy .env.example .env
# откройте .env и заполните KEITARO_URL, KEITARO_API_KEY, DEFAULT_DOMAIN, CAMPAIGN_NAME_PREFIX

# 3. Миграции базы данных (создают таблицы в файле adrobot.db)
alembic upgrade head

# 4. Сервер
uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000. Быстрая проверка связи с Keitaro: http://127.0.0.1:8000/api/offers
должен вернуть список офферов. Какой Keitaro и какой ключ (последние 4 символа) использует приложение,
видно на http://127.0.0.1:8000/api/info.

### Настройки (`.env`)

| Переменная | Назначение |
|---|---|
| `KEITARO_URL` | Адрес трекера, например `https://tlgk.host` |
| `KEITARO_API_KEY` | Ключ Admin API (в Keitaro: Профиль, API ключи) |
| `DEFAULT_DOMAIN` | Домен для новых кампаний, как в админке (например `kylovoa.com`) |
| `DEFAULT_GROUP`, `DEFAULT_SOURCE` | Название группы и источника (по умолчанию `FORTESTS`) |
| `CAMPAIGN_NAME_PREFIX` | Защита общего аккаунта: приложение создаёт и меняет только кампании с этим префиксом в названии (например `test_фамилия_`) |
| `REDIRECT_URL` | Куда ведёт первый поток (по умолчанию `https://google.com`) |
| `DATABASE_URL` | Строка подключения к БД (по умолчанию SQLite-файл `adrobot.db`) |
| `ENV_FILE` | Необязательно: путь к другому файлу настроек (используется для демонстрации на заглушке) |

Файл `.env` содержит секреты и не попадает в репозиторий (он в `.gitignore`). Настройки читаются при каждом
запросе, поэтому правка `.env` действует без перезапуска сервера.

## Миграции базы данных

Приложение хранит в локальной БД черновик таблицы офферов, снимок состояния Keitaro, кэш списка офферов
и журнал созданных кампаний. Структура таблиц описана моделями SQLAlchemy (`app/models.py`), а создаёт и
обновляет её **Alembic**.

```bash
alembic upgrade head        # применить все миграции (создать или обновить таблицы)
alembic current             # какая версия схемы сейчас в БД
alembic history             # список всех миграций
alembic downgrade -1        # откатить последнюю миграцию
```

Когда выполнять `alembic upgrade head`:

- при первом запуске проекта;
- после обновления кода, если в `alembic/versions/` появились новые файлы миграций;
- при запуске с другой базой, например для заглушки (`ENV_FILE=.env.mock` создаёт отдельный `mock.db`).

Адрес БД Alembic берёт из тех же настроек (`DATABASE_URL`), что и приложение. Команда безопасна для
повторного запуска: уже применённые миграции пропускаются (версия хранится в таблице `alembic_version`).

Сейчас есть одна миграция, `0001_initial_tables`: она создаёт таблицы `campaigns`, `streams`, `stream_offers`,
`offers_cache` и `created_campaigns`.

Если нужно изменить структуру таблиц, то следует править модель в `app/models.py` и создать миграцию:

```bash
alembic revision --autogenerate -m "описание изменения"
alembic upgrade head
```

Сбросить локальные данные можно удалением файла `adrobot.db` и повторным `alembic upgrade head`. Данные в Keitaro
это не затрагивает: черновик таблицы восстанавливается кнопкой `FETCH STREAMS FROM KT`.

## Безопасность

- Приложение пишет в Keitaro только в двух случаях: создание новой кампании и `PUSH TO KT`, который меняет
  **только список офферов** одного потока. Поток-редирект, фильтры и чужие кампании не затрагиваются.
- При заданном `CAMPAIGN_NAME_PREFIX` кампании без этого префикса нельзя ни загрузить, ни изменить,
  ни создать, и они не показываются в подсказках. Это защита от случайной правки чужих кампаний на общем аккаунте.
- Ключ Admin API хранится только в `.env` и целиком нигде не отображается.
- В шапке интерфейса всегда показан адрес Keitaro, к которому подключено приложение.

## Проверка работы

### Ограничения тестового окружения

В тестовом аккаунте Keitaro доступен **один оффер** (18813), создавать офферы у тестовой роли нельзя.
Поэтому проверка разделена на две части.

**A. Боевой Keitaro (один оффер).** Проверяется то, что возможно с одним оффером:

1. Создание кампании: `Name` с префиксом, `Geo`, оффер `18813`. В Keitaro появляется кампания с нужными
   доменом, группой, источником и двумя потоками.
2. `FETCH` кампании: потоки и оффер загружаются.
3. Удаление и возврат: `REMOVE` единственного оффера, `PUSH TO KT` (с подтверждением пустого потока),
   в Keitaro поток без офферов; затем `BRING BACK`, `PUSH TO KT`, оффер снова в Keitaro на 100%.
4. Закрепление доли (клик по проценту) и `PUSH TO KT`.
5. Ошибки: несуществующий оффер, некорректный гео-код, чужая кампания.

**Б. Демонстрация на заглушке Keitaro.** Сценарии с несколькими офферами (ADD, пересчёт долей, закрепление,
CANCEL) показываются на заглушке `dev/mock_keitaro.py`. В ней 4 оффера, у мок-офферов в названии `[MOCK]`.

```bash
# терминал 1: заглушка Keitaro
uvicorn dev.mock_keitaro:app --port 9000

# терминал 2: приложение с отдельными настройками и отдельной базой (mock.db)
copy dev\env.mock.example .env.mock          # Mac/Linux: cp dev/env.mock.example .env.mock
set ENV_FILE=.env.mock                        # Mac/Linux: export ENV_FILE=.env.mock
alembic upgrade head                          # миграции для базы заглушки
uvicorn app.main:app --port 8001
```

Откройте http://127.0.0.1:8001, ID кампании в заглушке: `216512`. Приложение можно держать на порту 8000
в другом терминале (без `ENV_FILE`).

## Как это устроено

Keitaro хранит настоящее состояние потоков. В локальной БД лежит **черновик** таблицы и снимок того,
что сейчас в Keitaro (`synced_*`). По разнице между ними таблица подсвечивается как несохранённая,
а `CANCEL` возвращает снимок. Расчёт долей вынесен в чистые функции (`services/weights.py`) и покрыт тестами,
HTTP-слой тонкий: вся логика в `services/`, а все обращения к Keitaro в `keitaro_client.py`.
